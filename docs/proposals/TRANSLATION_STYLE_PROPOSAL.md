## 1. น้ำเสียงและระดับภาษา

เกมเป็นการล้อเลียนชีวิตมหาวิทยาลัยด้วยอารมณ์ขันแห้งแบบอังกฤษ ภาษาไทยควรอ่านแล้วเป็นธรรมชาติและตลกเพราะสถานการณ์ ไม่ใช่เพราะพยายามขำ

- **ระดับภาษา:** ภาษากึ่งทางการแบบสื่อสารสมัยใหม่ ไม่ใช้ราชาศัพท์ ไม่ใช้ภาษาราชการ ("ดำเนินการ", "ทั้งนี้") ยกเว้นเมื่อต้นฉบับตั้งใจล้อความเป็นทางการ
- **สรรพนามผู้เล่น:** "คุณ" เป็นค่าเริ่มต้น เลี่ยง "ท่าน" และหลีกเลี่ยงการระบุเพศ
- **คำลงท้าย (ครับ/ค่ะ/นะ/จ้ะ):** ไม่ใช้ในข้อความระบบ เพื่อเลี่ยงการระบุเพศผู้พูด ใช้ได้เฉพาะเสียงตัวละครหรือประกาศที่ต้นฉบับกำหนดบุคลิกชัดเจน และต้องบันทึกไว้ในหมายเหตุ
- **แยกตามประเภทข้อความ:**
  - ป้าย/ปุ่ม/เมนู: วลีนามหรือกริยาสั้น ไม่มีคำลงท้าย ไม่มีจุด
  - Tooltip/คำอธิบาย: ประโยคสั้น ภาษาพูดเบา ๆ
  - บทเรียน/Tutorial: เป็นกันเองแต่ชัดเจน คำสั่งต้องทำตามได้โดยไม่ต้องเดา
  - ข้อความตลก/ประกาศ/ชื่อกิจกรรม: อิสระด้านภาษามากที่สุด (ดูข้อ 3)
  - แจ้งเตือนที่กระทบเกมเพลย์ (เงินหมด ผิดพลาด): ชัดก่อนตลก

## 2. ความกระชับ

ภาษาไทยไม่เว้นวรรคระหว่างคำและมักยาวกว่าอังกฤษในปุ่มแคบ แต่ความกว้างจริงขึ้นกับฟอนต์และ layout ซึ่ง QA ต้องวัดในเกม ข้อเสนอนี้เป็นแนวทางเริ่มต้นเท่านั้น

- ใช้คำสั้นที่คนใช้จริง เลือก "ซ่อม" แทน "ดำเนินการซ่อมแซม" ตัดคำเชื่อมที่ไม่จำเป็น ("การ", "ความ") เมื่อความหมายไม่เสีย
- ป้ายและปุ่ม: เป้าหมายความยาวไม่เกินต้นฉบับมากนัก ถ้าเกินประมาณ 1.3 เท่าของจำนวนอักขระต้นฉบับ ให้ใส่ธง `LENGTH` และเสนอตัวเลือกสั้นกว่า
- ห้ามแก้ปัญหาความยาวด้วยการเว้นวรรคแปลก ๆ, ตัดคำกลางคำ, หรือใส่อักขระตัดคำเอง
- ตัวเลขใช้เลขอารบิกตามต้นฉบับ หน่วยและสัญลักษณ์ (%, $, k, m) คงตามต้นฉบับ
- คำย่อ: ใช้เฉพาะที่ Glossary อนุมัติ ไม่คิดคำย่อใหม่เอง

## 3. การรักษามุก

เป้าหมายคือ "คนไทยหัวเราะที่จุดเดียวกับที่ต้นฉบับตั้งใจ" ไม่ใช่แปลตรงตัว

**ระดับการแปลมุก** (ผู้แปลเลือกและบันทึกใน `joke_tier`):

- **T0 ไม่มีมุก:** แปลตามปกติ
- **T1 แปลตรงแล้วยังตลก:** (สถานการณ์ตลกในตัว) แปลตรง รักษาโครงประโยคและจังหวะ (ตัวหักมุกอยู่ท้ายประโยคเหมือนเดิม)
- **T2 ดัดแปลง:** มุกอิงวัฒนธรรมอังกฤษ/เล่นคำ แต่ความหมายเดิมยังสื่อได้ ปรับตัวอย่างให้คนไทยเข้าใจ รักษาจุดประสงค์ของมุก
- **T3 แทนที่:** มุกเล่นคำที่ข้ามภาษาไม่ได้ เขียนมุกไทยใหม่ที่ทำหน้าที่เดียวกัน (ตำแหน่ง น้ำเสียง ขนาด) และต้องมีหมายเหตุอธิบายต้นฉบับและเหตุผล

**กฎ**
- ห้ามอธิบายมุกในตัวข้อความ (ไม่ใส่วงเล็บ "ล้อเลียน...")
- ไม่เพิ่มมุกในข้อความที่ต้นฉบับไม่ตลก และไม่ตัดมุกทิ้งเพราะแปลยาก ถ้าแปลไม่ได้จริงให้ธง `JOKE_UNRESOLVED` แล้วเสนอ 2–3 ตัวเลือก
- ความยาวของมุก T3 ต้องไม่เกินที่ที่ UI รองรับ
- มุกที่อ้างบุคคลจริง/แบรนด์จริง/เหตุการณ์จริงของไทย ห้ามใส่เอง ผู้แปลเสนอได้แต่ต้องให้ Controller อนุมัติ
- ชื่อวิชา คณะ ชื่อห้อง ชื่อสิ่งของที่เป็นล้อเลียน ใช้ Glossary เพื่อให้ชื่อเดียวกันตลอดเกม
- **ห้ามนำข้อความ Museum มาใช้เป็นข้อความ Campus** (ตามข้อกำหนดใน AGENT_TASKS.md) ถ้า Controller ต้องการให้ใช้ Museum เป็นอ้างอิงด้านศัพท์ ให้ระบุเป็นข้อความอ้างอิงแยกต่างหากและให้ผู้แปลตัดสินใจรายข้อ

## 4. กฎรักษา placeholders และ markup

**หลักการ: ทุกอย่างที่ไม่ใช่ข้อความที่มนุษย์อ่านต้องออกจากการแปลเหมือนเข้าทุกไบต์** ผู้แปลไม่ "ซ่อม" token ที่ดูผิด ให้ธงแล้วถาม

### 4.1 Token ที่ต้องคงเดิม (ตัวอย่างรูปแบบทั่วไป ยืนยันกับ schema จริงภายหลัง)

| ประเภท | ตัวอย่างรูปแบบ | กฎ |
|---|---|---|
| Placeholder แบบมีดัชนี/ชื่อ | `{0}`, `{name}`, `{[Term]}` | คัดลอกตรงตัว ห้ามแปลชื่อข้างใน ห้ามเว้นวรรคในปีกกา |
| Format แบบ printf | `%s`, `%d`, `%1$s` | คัดลอกตรงตัว จำนวนและชนิดต้องเท่าต้นฉบับ |
| Rich text/TMP tag | `<b>…</b>`, `<color=#ff0000>…</color>`, `<size=80%>`, `<sprite name="x">`, `<br>` | คัดลอก tag ทั้งหมด เปิด-ปิดครบคู่ ไม่เปลี่ยนค่าแอตทริบิวต์ ไม่เพิ่ม tag |
| ตัวสแลชแบบ escape | `\n`, `\t`, `\"` | จำนวนต้องเท่าต้นฉบับ ห้ามแปลงเป็นบรรทัดจริงหรือกลับกัน |
| อ้างอิง term/key ภายใน | เช่น `[i2s_…]`, `@Key@`, `$VAR$` | คัดลอกตรงตัว ห้ามแปล |
| อักขระควบคุมและช่องว่างพิเศษ | NBSP, ZWSP, ท้ายบรรทัด | คงตามต้นฉบับ ห้ามเพิ่มเอง |

### 4.2 การสลับลำดับ

ภาษาไทยมีลำดับคำต่างจากอังกฤษ จึงอนุญาตให้สลับตำแหน่ง token **เฉพาะ token ที่มีดัชนีหรือชื่อ** (`{0}`, `{1}`, `{name}`, `%1$s`) ส่วน token แบบไม่มีดัชนี (`%s %s`, `%d %d`) ห้ามสลับ ถ้าประโยคไทยธรรมชาติต้องสลับ ให้ธง `REORDER_NEEDED` ให้ Controller ตัดสินใจ

### 4.3 Tag ที่ครอบข้อความ

ข้อความระหว่าง tag แปลได้ แต่ tag ต้องครอบสิ่งที่ตรงกันในความหมาย ถ้าต้นฉบับ `<b>Happy</b> students` ฉบับไทยคือ `นักศึกษา<b>มีความสุข</b>` ได้ ถ้าหาคำที่ครอบเทียบเท่าไม่ได้ ให้ธงและห้ามย้าย tag ไปครอบคำอื่นโดยเงียบ ๆ

### 4.4 พหูพจน์และเพศ

ภาษาไทยไม่มีรูปพหูพจน์ ถ้าต้นฉบับแยก key เอกพจน์/พหูพจน์ ให้แปลทั้งสอง key เป็นข้อความที่ใช้ได้กับเลขใดก็ได้ (ใช้ลักษณนามที่เหมาะ เช่น "{0} คน" ไม่ใช้ "นักศึกษา 1 คน/นักศึกษาหลายคน") และใส่ธง `PLURAL_COLLAPSED` เพื่อให้ Controller ตรวจกลไก key

### 4.5 การเว้นวรรครอบ token (เสนอเป็นค่าเริ่มต้น QA ต้องทดสอบในเกม)

- ตัวเลข + หน่วย/ลักษณนามไทย: ติดกันหรือเว้น 1 ช่องอย่างสม่ำเสมอทั้งโปรเจกต์ **ข้อเสนอ: เว้น 1 ช่อง** (`{0} คน`, `{0} วัน`) เพื่อให้ token ถูกตัดแยกชัดเจนและอ่านง่าย
- token ที่อาจเป็นชื่อภาษาอังกฤษหรือข้อความอิสระ (`{name}`): เว้น 1 ช่องคั่นระหว่างข้อความไทยกับ token
- ห้ามเว้นวรรคแบบบังคับ (NBSP) หรือ ZWSP เพื่อช่วยตัดบรรทัดเอง จนกว่า Controller ยืนยันพฤติกรรมการตัดบรรทัดของเอนจิน

### 4.6 อักขระไทยและการเข้ารหัส

- ใช้ Unicode ที่เป็นมาตรฐาน: ลำดับ พยัญชนะ → สระบน/ล่าง → วรรณยุกต์ (เช่น `ก + ิ + ้`) ใช้ `ำ` (U+0E33) ตัวเดียว ห้ามแยกเป็น นิคหิต + สระอา
- ห้ามใช้อักขระผสมจากการคัดลอกที่อาจมีอักขระมองไม่เห็น ตรวจด้วยสคริปต์ก่อนส่ง
- เครื่องหมายวรรคตอนใช้ตามต้นฉบับ (`"`/`“”`, `...`/`…`, `!`) ไม่ใช้ "ฯ" "๚" หรือ ๆ เว้นแต่จำเป็นจริง การใช้ "ๆ" ได้ในภาษาพูดแต่ต้องไม่ทำให้คำยาวขึ้นเกินจำเป็น
- ห้ามแปลงเลขเป็นเลขไทย (๑๒๓) เว้นแต่ Controller สั่งเป็นกรณี
- เพื่อป้องกันปัญหาฟอนต์ ตัวอักษรที่ใช้ต้องอยู่ในช่วง Thai (U+0E01–U+0E5B) และ ASCII เท่านั้น อักขระอื่นต้องขออนุมัติ

### 4.7 บรรทัดใหม่

คงจำนวนและตำแหน่งตัวแบ่งบรรทัดตามต้นฉบับเมื่อความหมายอนุญาต ไม่ใส่ตัวแบ่งบรรทัดใหม่เพื่อแก้ความกว้างเอง ให้ธง `WRAP_CONCERN` ถ้าบรรทัดไทยยาวผิดปกติ

## 6. ชื่อเฉพาะ

เสนอให้คงรูปภาษาอังกฤษสำหรับชื่อตัวละคร ชื่อแบรนด์ในเกม และชื่อสิ่งที่เป็นมุกเล่นคำที่ไม่มีคำไทยเทียบเท่า (ประหยัดความกว้างและค้นหาง่าย) ยกเว้นกรณีที่ชื่อนั้นเป็นมุกที่ต้องแปล (T2/T3) ซึ่งแปลหรือถอดเสียงตาม Glossary **Controller เป็นผู้ตัดสินนโยบายนี้**

## 7. ข้อมูลที่ผู้แปลจะบันทึกต่อข้อความ

เสนอให้ record มีฟิลด์เหล่านี้ (นอกเหนือจาก stable ID, source, Thai, context, batch, review status ที่ README ระบุ)

- `translator_note`: เหตุผลการเลือกคำ/ที่มาของมุก
- `joke_tier`: T0–T3
- `flags`: `LENGTH`, `WRAP_CONCERN`, `REORDER_NEEDED`, `PLURAL_COLLAPSED`, `AMBIGUOUS`, `JOKE_UNRESOLVED`, `TOKEN_ANOMALY`
- `alt`: ตัวเลือกอื่น (ถ้ามี)
- `max_len_hint`: ความยาวสูงสุดที่ทราบจาก UI (ถ้า Controller ให้ข้อมูล)

## 8. คำถามและข้อมูลที่ต้องการจาก Controller

1. รูปแบบ source schema จริงของ Campus: ชนิด placeholder/markup/escape ที่ปรากฏจริง และมีระบบ key เอกพจน์/พหูพจน์หรือไม่
2. ข้อความ Campus ที่ extract ได้แล้วมี **บริบท** (หมวด UI, ตำแหน่งที่ใช้, ความยาวสูงสุด) หรือไม่
3. เอนจินตัดบรรทัดไทยทำงานอย่างไร และอนุญาตให้ใช้ ZWSP/NBSP ได้หรือไม่ (รอผลจาก prototype)
4. ฟอนต์ไทยที่จะใช้ครอบคลุมอักขระใดบ้าง และมีข้อจำกัดอักขระหรือไม่
5. นโยบายชื่อเฉพาะ (ข้อ 6) และสรรพนาม/คำลงท้าย (ข้อ 1)
6. จะให้ใช้ Museum เป็นข้อความอ้างอิงด้านศัพท์ไทยหรือไม่ และถ้าใช้ ให้ส่งมาเป็นชุดแยก
7. ช่องทางส่งงาน: ผู้แปลยังเข้าถึง GitHub remote ไม่ได้ ต้องการให้ส่งเป็นไฟล์ใน `docs/proposals/` หรือรอสิทธิ์สำหรับ branch/PR

## 9. ข้อเสนอลำดับถัดไป

เมื่อได้ source extraction แล้ว ผู้แปลเสนอแปลชุดตัวอย่างเล็ก (ประมาณ 40–60 ข้อความ) ที่ครอบคลุม: ป้ายปุ่มสั้น, tooltip, ประโยคที่มี placeholder หลายตัว, ข้อความมี rich text tag, ข้อความหลายบรรทัด, ข้อความตลก T1–T3, และชื่อวิชา/ห้อง เพื่อสรุป Glossary ให้ Controller อนุมัติก่อนแปลจำนวนมาก

## 10. รายการตรวจก่อนส่งทุกชุด

- จำนวนและชนิด token ต้นฉบับ = ฉบับแปล (ตรวจด้วยสคริปต์ ไม่ใช้สายตา)
- tag เปิด-ปิดครบ ไม่มีการเว้นวรรคเข้าไปใน tag
- จำนวน `\n` เท่าเดิม
- ไม่มีอักขระนอกช่วง Thai/ASCII และไม่มีอักขระมองไม่เห็น
- ใช้คำตาม Glossary ตรงกันทั้งชุด
- ทุกข้อความที่ธงมีหมายเหตุ
